# Offline Downloads: Implementation Plan

**Goal:** let the user download any episode (and movie) from a Jellyfin server, keep it in an app-managed folder, and play it in Blink's own player, both while online and with no server connection at all.

This document makes the architectural decisions up front so the implementing agent does not have to. Where it says **Decision**, follow it. Where it says **Spike**, check the assumption before building on it, and use the fallback if the check fails.

**Platform reality check.** The WebView decides what plays: WebView2/Chromium on Windows, WKWebView on macOS, WebKitGTK on Linux. On Windows WebView2, many real-world files will **not** play as-is: AC3, EAC3, DTS or TrueHD audio; HEVC without the HW extension; MKV on Linux and macOS. That is why Jellyfin transcodes or remuxes when streaming. A downloads feature that only saves the original file would therefore fail for a large share of episodes. **Decision:** support two download modes (§2).

## 1. Scope

**In scope (v1)**
- Download single Episodes and Movies (`BaseItemKind.Episode | Movie`, video only).
- Download a whole season (bulk enqueue of its episodes).
- Download queue with progress, pause, resume, cancel, retry, and delete.
- Resume across app restarts (byte-range resume for files; per-segment resume for HLS).
- Play downloaded items in Blink's existing video player (online and offline), with subtitles, chapters, media segments (intro skip), resume position, and a next-episode queue made of downloaded episodes.
- Offline start: if the server is unreachable at launch, land on the Downloads page instead of the error screen.
- Sync watched state and position back to the server when it is reachable again.
- Settings: download folder (default under the app's local data dir), "prefer downloaded copy", default quality.

**Out of scope (v1)**: music and audiobooks, photos (existing), trickplay thumbnails offline, burning image subtitles into HLS downloads, background downloads while the app is closed, mobile targets, an auto-delete-after-watched policy. Leave clean extension points; don't build these.

## 2. Key decisions

### D1. Download engine lives in Rust (custom commands), not the JS plugin
Multi-GB transfers need streaming to disk, `Range` resume, cancellation, throttled progress, and survival of webview reloads. Implement a `DownloadManager` in Rust (tokio, `reqwest`), exposed through Tauri commands and events. Leave `tauri-plugin-upload` alone; photos keep using it.

### D2. Two download modes, chosen automatically per item
1. **`file` mode (original file).** Used when the server's PlaybackInfo, requested with Blink's own `DeviceProfile`, returns `SupportsDirectPlay === true` for the chosen media source and the user chose "Auto" or "Original". URL: `GET {basePath}/Items/{itemId}/Download?mediaSourceId={msId}` (this is the official download endpoint; it supports Range). Saved as `media.{container}`.
2. **`hls` mode (compatible copy).** Used otherwise, or when the user picks a lower quality. Take the `TranscodingUrl` from PlaybackInfo (requested with the chosen `audioStreamIndex`, `subtitleStreamIndex: -1`, and `MaxStreamingBitrate` set to the chosen quality). Download `master.m3u8`, then the variant playlist, then every segment (and the `#EXT-X-MAP` init segment if present), sequentially. Write a rewritten local `index.m3u8` with relative URIs, `#EXT-X-PLAYLIST-TYPE:VOD` and `#EXT-X-ENDLIST`. Playback then goes through the **same hls.js path the player already uses for transcodes**, so seeking and duration just work.
   - Why not a single progressive transcoded MP4? Jellyfin's progressive transcodes are fragmented MP4 with an empty moov (unknown duration, unreliable seeking). HLS VOD playlists carry exact segment durations.
   - When finished, or on cancel, call `DELETE /Videos/ActiveEncodings?deviceId={api.deviceInfo.id}&playSessionId={id}` so the server stops the transcode.

### D3. Respect server permissions
- If `currentUser.Policy.EnableContentDownloading !== true`, the download UI is shown **disabled** with the tooltip "Your server administrator has disabled downloads for this account". Do not work around it with stream URLs.
- `hls` mode additionally needs `EnableVideoPlaybackTranscoding` or `EnablePlaybackRemuxing`. If the server refuses (PlaybackInfo has no `TranscodingUrl`, or `ErrorCode` is set), fail with a clear message.

### D4. Local media is served by a loopback HTTP server in Rust (not `asset://`)
The player needs Range requests for seeking, CORS (the `<video>` has `crossOrigin="anonymous"` and hls.js uses XHR), and correct MIME types. It also has to work on WebKitGTK, where custom-scheme media playback via GStreamer is unreliable. **Decision:** start an `axum` server on `127.0.0.1:<random port>` (use the existing `portpicker` dependency) at app start:
- Base URL: `http://127.0.0.1:{port}/{token}/`, where `token` is a random 32-hex string per app run. Requests without the correct token return 404.
- Serves only files under the downloads root (`tower-http::services::ServeDir`, which handles Range, 206, and conditional requests). Reject any path containing `..` or absolute components.
- Headers: `Access-Control-Allow-Origin: *`; MIME for `.m3u8` → `application/vnd.apple.mpegurl`, `.ts` → `video/mp2t`, `.mkv` → `video/x-matroska`, `.vtt` → `text/vtt`, `.ass/.ssa` → `text/plain`, `.sup` → `application/octet-stream`.
- Methods: GET and HEAD only.
- Use `127.0.0.1` literally, never `localhost`. Loopback counts as "potentially trustworthy", so there are no mixed-content issues from `tauri://` or `http://tauri.localhost` origins.

**Spike (Task 0):** confirm on Windows WebView2 that an MP4 and an H.264/AAC MKV play and seek from this server, and that a local HLS folder plays and seeks via react-player. Smoke-test macOS and Linux if available. *Fallback if WebView2 refuses loopback media (unlikely):* register a Tauri async URI scheme protocol `blinkmedia` with the same handler logic.

### D5. Storage location: app local data dir, user-changeable, never the install dir
The user suggested "in the install folder". **Don't.** On Windows, the NSIS updater (`installMode: passive`) and the uninstaller rewrite or remove the install dir, and a per-machine install under Program Files is not writable. On macOS the `.app` bundle is signed and read-only. AppImage is read-only. **Default root:** `{appLocalDataDir}/downloads` (Windows: `%LOCALAPPDATA%\com.blink.prayag17\downloads`). Settings provide "Change folder…" (dialog plugin, `directory: true`) and "Open folder" (shell `open`).

Layout (fixed short names avoid sanitisation and `MAX_PATH` trouble):
```
{root}/
  .blink-downloads              # marker file (version) so we never treat a random folder as ours
  {serverId}/{itemId}/
    manifest.json               # single source of truth for this download
    media.{container}           # file mode   (".part" suffix while downloading)
    hls/index.m3u8              # hls mode    (+ hls/seg00000.ts …, hls/init.mp4)
    subs/{streamIndex}.{vtt|ass|ssa|sup}
    images/primary.jpg          # episode/movie primary
    images/series-primary.jpg   # episodes only
    images/backdrop.jpg         # series backdrop (episodes) or item backdrop (movies)
```
`serverId` and `itemId` are Jellyfin GUIDs. Validate them against `^[0-9a-fA-F-]{1,64}$` in Rust and reject anything else.

### D6. Single writer: Rust owns `manifest.json`
TS sends all metadata in the enqueue call. Rust writes the manifest, then updates `status`, `progress`, `error` and `userState` under a per-download mutex. Writes are atomic (write `manifest.json.tmp`, then rename). TS never writes files directly. On startup, Rust scans `{root}/*/*/manifest.json` to rebuild the list, so this works even if every `.dat` store is wiped.

### D7. Queue policy
- One media transfer at a time (FIFO). Small assets (images, subtitles, segments JSON) are fetched inline before the media job starts.
- On app start, any manifest with status `downloading` or `queued` becomes **`paused`** (no surprise bandwidth use). The Downloads page shows a "Resume all" button.
- Enqueuing is idempotent by `downloadId = "{serverId}:{itemId}"`. Re-enqueuing a `completed` item is a no-op; a `failed` or `paused` one resumes.

### D8. Auth
Rust receives the header value of `api.authorizationHeader` (`MediaBrowser … Token="…"`) as `Authorization` per job. Do **not** put `api_key` in download URLs (keeps tokens out of logs and manifests). Never persist the token in the manifest. Resume and retry take a fresh header from TS (the current `api`). If the server returns 401 or 403, set status to `failed` with error code `unauthorized`.

### D9. Local playback reuses the existing player and store
Add `origin: "server" | "local"` to `usePlaybackStore`. Write a new `initializeLocalPlayback()` that fills the **same** store shape from a manifest. A new route `/local/player` renders the existing exported `VideoPlayer` component outside the `_api` guard. Player code branches on `origin` only where it touches the server (list in §6.4). Do not fork the player.

### D10. Playstate when local
- Always save position and played state into `manifest.userState` (via a Rust command), throttled to every 10 s, plus on pause, exit and end.
- If the manifest's `serverId` and `userId` match the current API **and** the server responds, report to the server as well (`PlayMethod.DirectPlay`, `PlaySessionId: null`, the manifest's `mediaSourceId`).
- If reporting fails or is impossible, set `userState.pendingSync = true`. Sync later (§7) with **last-write-wins on timestamp**: push only when local `lastPlayedAt` is newer than the server's `UserData.LastPlayedDate`.

### D11. Audio and subtitle tracks are fixed at download time
- Audio: the download dialog asks which audio track (default: the same preference logic as `initializePlayback`). In `hls` mode it is baked in. In `file` mode the WebView can't switch embedded audio tracks, so only the default track plays. If the file has more than one audio track and the user picked a non-default one, **force `hls` mode** (remux, cheap).
- Subtitles: download **all text subtitle streams** (SRT and WebVTT converted to `vtt`, ASS and SSA kept as `ass`/`ssa`) via `GET /Videos/{itemId}/{mediaSourceId}/Subtitles/{index}/0/Stream.{ext}`. For PGS, try `Stream.sup`; if that fails, skip the track and record `unavailable: true` in the manifest. The player's subtitle menu lists only available downloaded tracks.

### D12. Opening a downloaded item while online
Setting "Prefer downloaded copy when available" (default **on**). When on and a `completed` download exists for the item (same `serverId`), `PlayButton` starts local playback instead of streaming. The episode page also shows a "Downloaded" chip.

### 3.3 Data model (serde `rename_all = "camelCase"`; mirror it exactly in TS)
```rust
enum Status { Queued, Downloading, Paused, Completed, Failed }
enum Mode { File, Hls }
enum ErrorCode { Network, Unauthorized, NotFound, DiskFull, InsufficientSpace, ServerRefused, Io, Cancelled, Unknown }

struct Progress { bytes_done: u64, bytes_total: Option<u64>, segments_done: Option<u32>, segments_total: Option<u32> }

struct UserState { position_ticks: i64, played: bool, last_played_at: Option<String /*RFC3339*/>, pending_sync: bool }

struct Manifest {
  schema_version: u32,               // 1
  id: String,                        // "{serverId}:{itemId}"
  server_id: String, server_name: String, server_address: String, user_id: String,
  item_id: String, media_source_id: String,
  mode: Mode,
  media: MediaInfo,                  // { path, container, videoCodec, audioCodec, bitrate, audioStreamIndex, sizeBytes }
  subtitles: Vec<SubtitleInfo>,      // { streamIndex, codec, language, displayTitle, isDefault, isForced, path: Option, unavailable }
  images: Images,                    // { primary, seriesPrimary, backdrop } relative paths, all Option
  item: serde_json::Value,           // trimmed BaseItemDto (opaque to Rust)
  media_segments: serde_json::Value, // MediaSegmentDtoQueryResult or null (opaque)
  hls: Option<HlsInfo>,              // { quality, maxBitrate, segmentCount, playSessionId } for re-planning on resume
  status: Status, error: Option<ErrorInfo /*{code,message}*/>,
  progress: Progress,
  user_state: UserState,
  created_at: String, completed_at: Option<String>,
}

struct JobSpec {                     // what TS sends to enqueue/resume
  manifest: Manifest,                // status/progress ignored on input
  auth_header: String,
  media_url: String,                 // file: /Items/{id}/Download?...  hls: absolute master.m3u8 URL
  assets: Vec<AssetSpec>,            // { url, relPath } subtitles + images
  expected_bytes: Option<u64>,       // MediaSource.Size or bitrate*duration estimate
}
```

### 3.4 Commands (all `async`, return `Result<T, String>`; register in `invoke_handler`)
| Command | Behaviour |
|---|---|
| `downloads_init(root: Option<String>) -> InitInfo { root, mediaBaseUrl }` | Resolve root (None → `app_local_data_dir()/downloads`), create it and the marker, store it in the manager, scan manifests, demote `downloading`/`queued` → `paused`. Idempotent. |
| `downloads_list() -> Vec<Manifest>` | From the in-memory index. |
| `downloads_enqueue(job: JobSpec)` | Validate ids; check free space ≥ `expected_bytes * 1.05 + 200 MB`, else `InsufficientSpace`; write manifest (`queued`); push to queue. |
| `downloads_pause(id)` | Cancel token; keep partial data; status `paused`. |
| `downloads_resume(job: JobSpec)` | Same as enqueue but keeps existing progress (TS supplies a fresh URL and auth). |
| `downloads_cancel(id)` | Cancel, then delete the item folder (cancelling = discarding). |
| `downloads_delete(id)` | If active, cancel first; then `remove_dir_all` of the item folder; drop from the index; on Windows, retry 3× with a 500 ms wait (AV/indexer locks). |
| `downloads_update_user_state(id, userState)` | Merge and atomically write. |
| `downloads_free_space() -> u64` | `fs4::available_space(root)`. |
| `downloads_move_root(newRoot)` | Refuse if any job is `downloading`. Try `rename` per server folder; on cross-device error, copy then delete. Write the marker; update root; emit `downloads://root-changed`. |

Add the matching permissions in a new capability file `src-tauri/capabilities/downloads.json`, or simply rely on default app-command access (custom commands are allowed by default in Tauri 2 unless restricted). Verify with `pnpm tauri dev`.

### 3.5 Events (`app.emit`)
- `downloads://progress` → `{ id, bytesDone, bytesTotal, segmentsDone, segmentsTotal, speedBps }`, **at most 4 per second per job**.
- `downloads://status` → full `Manifest` whenever status or error changes (TS replaces its copy).
- Persist `progress` into the manifest at most every 5 s and on every status change. Never per chunk.

### 3.6 File job (`file_job.rs`)
1. `part = media.{ext}.part`. If it exists, `offset = len(part)`, else 0.
2. GET with `Range: bytes={offset}-` when offset > 0. Response handling:
   - `206`: append.
   - `200` while offset > 0: server ignored Range, so truncate `part` and start from 0.
   - `416`: if `offset == expected`, treat as complete, else truncate and restart.
   - `401/403` → `Unauthorized`; `404` → `NotFound`; other 4xx → `ServerRefused`; 5xx or network error → retry.
3. Stream chunks to a `BufWriter` (1 MiB); check the cancel token between chunks; `ENOSPC` → `DiskFull` (keep the partial).
4. On EOF: verify size against `Content-Range` total, else `Content-Length + offset`, else `expected_bytes` when known. On mismatch, retry. Then `fsync` and rename `part` → `media.{ext}`.
5. Retry policy for network or 5xx errors: 5 attempts with backoff 2/4/8/16/32 s, resuming from the current offset each time. Then `Failed{Network}`.
6. Connect timeout 15 s. Read timeout 60 s **per chunk**, not for the whole request.

### 3.7 HLS job (`hls_job.rs`)
1. GET master URL → parse the first `#EXT-X-STREAM-INF` variant URI (relative to the master URL) → GET the variant playlist.
2. Parse lines: keep `#EXTM3U`, `#EXT-X-VERSION`, `#EXT-X-TARGETDURATION`, `#EXT-X-MEDIA-SEQUENCE`, `#EXT-X-MAP` (rewrite URI → `init.mp4`), `#EXTINF` and the following URI (→ `seg{n:05}.{ts|mp4|m4s}`, extension taken from the URI path). Drop other tags. Append `#EXT-X-PLAYLIST-TYPE:VOD` (if missing) and `#EXT-X-ENDLIST`.
3. Store `segmentsTotal`. Write `hls/index.m3u8` **only after all segments complete** (write `index.m3u8.part` early for debugging).
4. Download segments **in order, one at a time** (the server transcodes on demand and sequential requests keep a single ffmpeg running). Skip a segment if the file exists and is non-empty and its index < `segmentsDone`. Each segment gets a 180 s timeout (the first segments may wait for the transcode to start), 3 retries.
5. Progress: `segmentsDone/segmentsTotal`; `bytesDone` is the sum written; `bytesTotal` is an estimate.
6. On completion, cancel or failure: best-effort `DELETE {basePath}/Videos/ActiveEncodings?deviceId=…&playSessionId=…` (TS passes `basePath`, `deviceId` and `playSessionId` in `HlsInfo`/`JobSpec`).
7. On resume after restart, TS re-requests PlaybackInfo with the same parameters (stored in `manifest.hls`) and passes the new master URL. Rust re-parses the variant playlist. **If the segment count or any `#EXTINF` duration differs from the stored playlist, delete `hls/` and restart from 0.**

### 3.8 Media server (`media_server.rs`)
- Spawn in `.setup()` with `tauri::async_runtime::spawn`. Hold the root in an `Arc<RwLock<PathBuf>>` shared with the manager so `move_root` takes effect.
- Route `/{token}/{*path}` → validate token (constant-time compare), then `ServeDir::new(root)` on `path`. Add CORS and MIME overrides (§D4).
- `InitInfo.mediaBaseUrl = "http://127.0.0.1:{port}/{token}"`.

### 3.9 Rust tests (`cargo test --manifest-path src-tauri/Cargo.toml`)
- `paths`: id validation, rejection of `..`/absolute/UNC paths, safe join.
- `manifest`: serde round-trip including unknown fields in `item` (opaque), atomic write leaves no `.tmp` behind, `scan_all` skips corrupt manifests (log, don't crash).
- `hls_job` parser/rewriter, with fixtures in `src-tauri/tests/fixtures/` (write realistic Jellyfin playlists: TS segments with query strings, fMP4 with `#EXT-X-MAP`, a master with one variant).
- `file_job` against an in-process axum test server: fresh download; resume after an interrupted stream (server drops the connection mid-body); server returns 200 to a Range request (must restart); 404 → `NotFound`; size mismatch → retry; cancel mid-transfer keeps the `.part`.
- `media_server`: wrong token → 404; `Range: bytes=0-99` → 206 with 100 bytes; traversal attempt → 404; CORS header present.

### 4.2 `useDownloadsStore` (zustand + immer)
State: `ready: boolean`, `mediaBaseUrl: string`, `root: string`, `items: Record<string, DownloadManifest>`, `progress: Record<string, ProgressEvent>`.
Actions: `init()`, `enqueue(job)`, `pause(id)`, `resume(id)`, `cancel(id)`, `remove(id)`, `resumeAll()`, plus selectors `getByItem(serverId, itemId)`, `completedForSeries(seriesId)`.
- `init()` reads the root from storage, calls `downloads_init`, loads the list, and subscribes (`listen`) to both events **once** (guard against StrictMode double-mount by keeping the unlisten handles at module level).
- Call `await useDownloadsStore.getState().init()` in `src/main.tsx` `init()` **before** rendering, so the route guards can query it. Wrap it in try/catch: a downloads failure must never prevent the app from starting.
- `resume(id)` needs an online `api`. It re-plans (fresh URL and auth) from `manifest.hls` or the media source id and calls `downloads_resume`. If offline, show the snackbar "Connect to {serverName} to resume".

### 4.3 `planDownload(api, user, serverInfo, item, options)` → `JobSpec`
Inputs: `options = { mediaSourceId?, audioStreamIndex?, quality: "auto" | "original" | "high" | "medium" | "low" }`.
Bitrates: high 20 Mbps, medium 8 Mbps, low 3 Mbps (put them in `src/utils/constants/downloads.ts`).

Steps:
1. Guard: `user.Policy?.EnableContentDownloading` must be true, else throw `DownloadNotAllowedError`.
2. Fetch the full item with `getUserLibraryApi(api).getItem` (fields MediaSources, MediaStreams, Chapters) and the series item if it is an episode (for its images).
3. `getMediaInfoApi(api).getPostedPlaybackInfo({ itemId, userId, mediaSourceId, audioStreamIndex, subtitleStreamIndex: -1, maxStreamingBitrate, playbackInfoDto: { DeviceProfile: playbackProfile } })`. For "original" or "auto" use `maxStreamingBitrate = 120_000_000`; for others use the quality bitrate.
4. Mode decision table (implement as a pure function `chooseMode()` and unit-test it):

   | quality | SupportsDirectPlay | non-default audio picked & >1 audio track | → mode |
   |---|---|---|---|
   | auto / original | true | no | `file` |
   | auto | false | any | `hls` |
   | auto / original | true | yes | `hls` |
   | original | false | any | `file`, plus a warning flag `mayNotPlay: true` (the UI asks for confirmation) |
   | high/medium/low | any | any | `hls` |
   | (hls chosen but no `TranscodingUrl`) | | | throw `ServerRefusedError` |

5. URLs: file → `${api.basePath}/Items/${itemId}/Download?mediaSourceId=${msId}`; hls → `${api.basePath}${source.TranscodingUrl}` (it already contains `PlaySessionId`; strip any `api_key` query parameter because auth goes in the header).
6. 8. Media segments: `getMediaSegmentsApi(api).getItemSegments({ itemId })`, which may 404 on older servers (store `null`).
9. `expected_bytes`: file → `source.Size`; hls → `(bitrate/8) * runtimeSeconds * 1.1`.
10. `trimItem()`: keep `Id, Name, Type, SeriesId, SeriesName, SeasonId, SeasonName, ParentIndexNumber, IndexNumber, Overview, RunTimeTicks, ProductionYear, PremiereDate, OfficialRating, CommunityRating, Chapters, MediaSources[chosen only, with MediaStreams], ImageBlurHashes, UserData`. ## 7. Sync (`sync.ts`)

`flushPendingPlaystate(api, serverId, userId)`. Call it in `ProviderWrapper` (`src/main.tsx`) once `api.accessToken` and `user.Id` are set, and again when the Downloads page "Retry connection" succeeds. For each manifest with `userState.pendingSync && serverId === current && userId === current`:
1. `getUserLibraryApi(api).getItem({ itemId, userId })` → server `UserData`. On 404, clear `pendingSync` (the item is gone) and continue.

Verify this method exists in `@jellyfin/sdk@0.13.0`. If it doesn't, use `reportPlaybackStart` then `reportPlaybackStopped` with `PositionTicks`.
4. Clear `pendingSync` via `downloads_update_user_state`. Run sequentially; errors leave the flag set.

## 8. Edge cases checklist (each must be handled; most map to a test)

- [ ] Server unreachable mid-download → retries, then `failed/network`; Resume works later.
- [ ] App killed mid-download → on restart the status is `paused`, partial data is kept, and Resume continues from the offset or segment.
- [ ] Server ignores Range (200) → restart cleanly, no corrupt append.
- [ ] Disk fills mid-download → `failed/diskFull`; pre-check prevents most cases (`insufficientSpace`).
- [ ] Item deleted on server → `failed/notFound`; existing completed downloads of it still play.
- [ ] Token expired or user logged out → `failed/unauthorized`; Resume after re-login works with the new header.
- [ ] Same item on two servers → separate ids and folders.
- [ ] Switching the default server or user → Downloads page still lists everything (grouped by server); progress syncs only to the matching server+user.
- [ ] Item with multiple MediaSources → dialog picks one; `mediaSourceId` is stored.
- [ ] File with several audio tracks, non-default chosen → forced `hls` mode.
- [ ] Image subtitles (PGS/VobSub/DVB) → PGS best-effort; others marked unavailable; the player never offers an unavailable track.
- [ ] Missing `RunTimeTicks` → skip size estimate (no space precheck beyond 200 MB) and skip the 90%-played rule.
- [ ] Delete while downloading → cancel first, then delete; no orphaned `.part`.
- [ ] Changing the download folder while a download is active → blocked with a message.
- [ ] Folder chosen that isn't empty and has no marker → create the `Blink Downloads` subfolder inside it rather than writing into the user's folder directly.
- [ ] Downloads root deleted externally → `downloads_init` recreates it; manifests are gone so the list is empty; no crash.
- [ ] Corrupt `manifest.json` → skipped with a log line; the folder appears under "Unrecognised" with a Delete option (optional; at minimum don't crash).
- [ ] Windows file locks on delete or rename → retries.
- [ ] HLS resume where the server returns a different segment layout → restart the HLS download from 0.
- [ ] Queue end in local playback → exit the player (same as today).
- [ ] Offline launch with zero downloads → existing error page, unchanged.
- [ ] StrictMode double effects → event listeners registered once; `init()` idempotent.
- [ ] Progress events don't re-render the whole app: components subscribe with selectors to `progress[id]` only.
